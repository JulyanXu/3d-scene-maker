# 3D 场景制作

先找出用户希望从哪个位置看见什么。把会决定成败的空间关系、材质或动作写成可实际检查的场景说明。沿用用户已有工程；新建场景时使用随 skill 提供的模板。

## 确定画面与依据

- 文字创作：确定首帧主体、尺度参照、前中后景、光线，以及靠近后值得看的细节。用户未指定的时间、材质和配色可自行选择。艺术、大尺度、微观或动态题材可查阅 [案例拆解](references/patterns.md)。
- 参考还原：先读取用户提供的图片或图纸，建立一致的单位和坐标。匹配画幅与相机，标出可以核对的轮廓、相对位置和遮挡。实测值、可见事实、推断分别记录，方法见 [按参考还原](references/reconstruction.md)。混合任务逐项区分需要忠实保留和允许创作的部分。
- 资料足够就开始。只有缺失信息会实质影响结果时才提问，例如用户要求按毫米落位却没有比例依据。若可以先完成比例建模，将未知尺寸明确标为估计。

## 制作与修改

1. 在新目录执行 `node "<本 skill 目录>/scripts/new-scene.mjs" "<目标工程目录>"`，进入目标工程后执行 `npm ci`。修改已有作品时从它的源码开始。
2. 在 `src/scene.js` 创建有名称的主体和环境组，集中管理尺寸、布局、相机与必要的动作。先用简单体块验证首帧和第二视角，观察主体轮廓、透视、接地与穿插，再投入细节。需要真实比例时以米为单位。
3. 优先利用用户提供的模型和贴图。额外素材选用允许当前使用及随源码再分发的资源，将作者、出处、许可、必要署名和改动写入工程的 `ASSETS.md`，保留所需许可文本；纯程序生成的作品注明生成方式。对重复几何使用实例化，对远景按需降低细节，保住辨识主体。
4. 注册首帧和至少一个检查空间关系的视角；提供镜头复位。根据需求设计交互。过程类场景让触发、主体变化和环境反应对应同一个时刻与位置。局部修改时沿用已有相机、尺寸、对象名称，从相同视角复查其他物件的位置。
5. 构建及测试命令和素材内嵌方式见 [工程与验收](references/build.md)。亲自打开构建后的文件，检查首帧、另一个视角和每个关键状态。观察拍摄范围、遮挡、材质和交互，发现问题继续修正。在 `scene-check.mjs` 中留下题材特有的行为或尺寸断言。

## 交付

提供可独立复制的 `scene.html` 和可重新构建的完整源码工程，无须分发 `node_modules`。给出成品及源码位置、关键操作、参考依据和影响还原的推断。交付前从源码重新构建，将 HTML 单独复制到空目录断网测试，并检查实际截图。未经核对的尺寸或不可见表面按推断说明。
